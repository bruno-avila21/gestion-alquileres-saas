Antes de tocar Railway

5 min
  1. Pusheá la rama. Railway construye desde GitHub. La rama fix/audit-2026-07-18 ya está en origin; si hacés commits nuevos, pusheá antes de desplegar.
  2. Tené a mano los secretos. Están generados en docs/propuesta-palavecino/secretos-prod.local.txt (gitignoreado). Vas a copiar de ahí JWT_SECRET, DOCUMENT_TOKEN_SECRET y REGISTRATION_INVITE_CODE. Postgres y MinIO de ese archivo no se usan: Railway genera sus propias credenciales.
  3. Plan de Railway. Entrá a railway.com. Si tu cuenta está en Trial, alcanza para armar todo; para que el demo quede en línea más de un mes conviene pasar a Hobby (USD 5/mes, incluye USD 5 de uso).
  4. Acceso al DNS de tu dominio. Vas a agregar un registro CNAME en el paso 5.
2

Proyecto, Postgres y Bucket

5 min
  1. En el panel: New Project → Empty project. Nombralo gestion-alquileres (arriba a la izquierda, Settings).
  2. + Create → Database → PostgreSQL. Queda un servicio llamado Postgres. No toques nada más.
  3. + Create → Bucket. Región: US East (la más cercana a Argentina). Dejale el nombre Bucket: las variables de abajo lo referencian con ese nombre.
  4. Abrí el Bucket → pestaña Credentials y fijate qué dice sobre el estilo de URL: virtual-hosted (lo normal hoy) o path-style. Lo vas a necesitar para una variable del paso 3.
Por qué Bucket y no MinIORailway Buckets es almacenamiento S3 nativo, privado, a USD 0,015 por GB al mes y sin costo de tráfico. Es un servicio menos que mantener y el código ya habla S3 (el mismo camino que usa MinIO en local).

Servicio api

10 min · la primera build tarda 4–6 min
  1. + Create → GitHub Repo → elegí bruno-avila21/gestion-alquileres-saas. Si no aparece, Configure GitHub App y dale acceso al repo.
  2. Antes de que termine la primera build, entrá al servicio → Settings:
    • Service name: api (exacto: el servicio web lo busca por ese nombre en la red privada).
    • Source → Branch: fix/audit-2026-07-18.
    • Source → Root Directory: /api. Railway detecta el Dockerfile solo.
    • Deploy → Healthcheck Path: /health/live.
    • Networking: no generes dominio público. Solo se llega por el servicio web.
  3. Pestaña Variables → Raw Editor y pegá este bloque completo. Reemplazá los tres valores marcados con <…> con los del archivo de secretos.
# Entorno
ASPNETCORE_ENVIRONMENT=Production
PORT=8080
ForwardedHeaders__Enabled=true
AllowedHosts=*

# Base de datos (referencias al servicio Postgres, Railway las resuelve)
ConnectionStrings__DefaultConnection=Host=${{Postgres.RAILWAY_PRIVATE_DOMAIN}};Port=5432;Database=${{Postgres.PGDATABASE}};Username=${{Postgres.PGUSER}};Password=${{Postgres.PGPASSWORD}}
ConnectionStrings__HangfireConnection=Host=${{Postgres.RAILWAY_PRIVATE_DOMAIN}};Port=5432;Database=${{Postgres.PGDATABASE}};Username=${{Postgres.PGUSER}};Password=${{Postgres.PGPASSWORD}}

# Fotos y documentos → Railway Bucket
Storage__Provider=S3
Storage__Bucket=${{Bucket.BUCKET}}
Storage__ServiceUrl=${{Bucket.ENDPOINT}}
Storage__Region=${{Bucket.REGION}}
Storage__AccessKey=${{Bucket.ACCESS_KEY_ID}}
Storage__SecretKey=${{Bucket.SECRET_ACCESS_KEY}}
Storage__ForcePathStyle=false

# Secretos (de secretos-prod.local.txt)
JwtSettings__SecretKey=<JWT_SECRET>
DocumentToken__Secret=<DOCUMENT_TOKEN_SECRET>

# Registro cerrado: el código permite sembrar SOLO la org demo
Registration__Mode=InviteCode
Registration__InviteCode=<REGISTRATION_INVITE_CODE>

# Origen público (mismo origen que el SPA; CORS no interviene pero la clave es obligatoria)
Cors__AllowedOrigins__0=https://demo.tudominio.com

# Email apagado para el demo (solo loguea)
Email__Provider=Null
Email__FromEmail=no-reply@demo.tudominio.com
Si…Entonces
El Bucket dice path-style en CredentialsCambiá Storage__ForcePathStyle=true.
Postgres no tiene PGDATABASE / PGUSER en su pestaña VariablesUsá los nombres que sí muestre (la base suele ser railway y el usuario postgres).
Le pusiste otro nombre al BucketReemplazá Bucket. por <TuNombre>. en las seis referencias.

Guardá con Deploy (o Update variables). En Deployments → View logs tiene que terminar en Now listening on: http://[::]:8080. Si el deploy queda en rojo, ver Si algo falla.

OjoAllowedHosts=* es correcto acá: la API no tiene dominio público y el healthcheck de Railway le pega con un Host interno. Restringirlo hace fallar el deploy.

Servicio web

5 min · build 2–3 min
  1. + Create → GitHub Repo → el mismo repo.
  2. Settings:
    • Service name: web.
    • Branch: fix/audit-2026-07-18. Root Directory: /web.
  3. Variables → Raw Editor:
PORT=8080
API_UPSTREAM=${{api.RAILWAY_PRIVATE_DOMAIN}}:8080

No definas SITE_ADDRESS. Con esa variable Caddy intentaría sacar un certificado propio; en Railway el TLS lo termina la plataforma y Caddy sirve HTTP plano en el 8080.

  1. Settings → Networking → Generate Domain, puerto 8080. Te da una URL *.up.railway.app para probar ya mismo, antes del DNS.
  2. Abrí esa URL: tiene que cargar el login del panel. Probá también …/health/live: si responde, Caddy ya llega a la API por la red privada.

5 min + propagación (minutos a horas)

  2. Railway te muestra un valor CNAME (algo como xxxx.up.railway.app). En el panel DNS de tu registrador creá:
TipoNombre / hostValor / destinoTTL

Si usás CloudflareDejá el registro en DNS only (nube gris), o bien poné el modo SSL en Full (strict). Con la nube naranja y SSL en Flexible entra en un bucle de redirecciones.
6

Migrar la base

3 min · desde tu PC

La API no migra al arrancar (a propósito). Corrés las migraciones una vez desde tu máquina contra la URL pública de Postgres.

  1. Servicio Postgres → Variables → copiá DATABASE_PUBLIC_URL. Tiene esta forma: postgresql://postgres:CLAVE@HOST.proxy.rlwy.net:PUERTO/railway.
  2. Armá la cadena de conexión con esos cuatro datos y corré, en PowerShell, dentro de la carpeta api:
cd api
dotnet ef database update `
  --project src/GestionAlquileres.Infrastructure `
  --startup-project src/GestionAlquileres.API `
  --connection "Host=HOST.proxy.rlwy.net;Port=PUERTO;Database=railway;Username=postgres;Password=CLAVE"
  1. Tiene que terminar en Done. Después, servicio api → menú ⋯ del último deploy → Restart, para que Hangfire cree su esquema sobre la base ya migrada.
RecordatorioEl proyecto exige --connection explícito: la fábrica del DbContext trae una cadena de marcador y sin ese flag no apunta a ninguna base real.

Cargar las 85 propiedades

10–15 min · desde tu PC

Los datos ya están scrapeados en tools/importar-sitio-tokko/salida-palavecino/ (propiedades y 647 fotos). El importador registra la organización con el código de invitación, sube todo por la API y publica.

cd tools/importar-sitio-tokko
pip install requests
python importar.py salida-palavecino `
  --api https://demo.tudominio.com/api/v1 `
  --slug palavecino `
  --email admin@palavecino.demo `
  --password "Palavecino2026!" `
  --nombre "Palavecino y Asociados" `
  --invite <REGISTRATION_INVITE_CODE> `
  --publicar

Si el dominio todavía no propagó, usá la URL *.up.railway.app del paso 4 en --api. Es idempotente: si se corta, volvé a correrlo y saltea lo que ya subió.

Después: cambios y costo

rutina

Ir viendo los cambios

Cada push a la rama configurada redeploya api y web solos (Railway solo reconstruye el servicio cuya carpeta cambió). Si un cambio trae una migración nueva, repetí el comando del paso 6 antes o justo después del deploy.

Cuando el cliente firme

  • Agregá su dominio real como segundo Custom Domain del servicio web y sumalo a Cors__AllowedOrigins__1.
  • Cerrá el registro: Registration__Mode=Disabled en la api.
  • Prendé el email: Email__Provider=Smtp y credenciales (Resend o Brevo tienen plan gratis).

Controlar el gasto

En Usage del proyecto ves el consumo diario. Para pausar el demo sin perder nada: servicio → Settings → Remove service solo en api y web (Postgres y Bucket cuestan centavos y conservan los datos). Volver a crearlos son los pasos 3 y 4.

Si algo falla

La build de api o web falla en segundos
Casi siempre es el Root Directory vacío o sin la barra inicial. Tiene que ser /api o /web.
api arranca y se cae (crash loop)
Mirá los logs. "SecretKey must be at least 32 characters": secreto mal pegado. "Registration mode Open is not allowed": falta Registration__Mode. "Connection refused" a Postgres: revisá que las referencias ${{Postgres.…}} se hayan resuelto (en Variables aparecen con el valor real al pasar el mouse).
web responde 502 en /api o /health
Caddy no encuentra la API. Confirmá que el servicio se llama exactamente api y que API_UPSTREAM termina en :8080.
Las fotos dan 500 al subir o al verse
Problema con el Bucket. Alterná Storage__ForcePathStyle según lo que diga la pestaña Credentials, y verificá que Storage__ServiceUrl sea la URL completa con https://.
El dominio queda en "Waiting for DNS"
Propagación. Comprobá desde tu PC con nslookup demo.tudominio.com: tiene que devolver el CNAME de Railway. Si usás Cloudflare, nube gris.
El importador devuelve 401 o 403 al registrar
El código de --invite no coincide con Registration__InviteCode de la api. Copialo de nuevo, sin espacios.
Login funciona pero la sesión se pierde al recargar
La cookie sale sin Secure. Falta ForwardedHeaders__Enabled=true en la api.
